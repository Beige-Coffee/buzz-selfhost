Run Buzz on your own server

Buzz is open-source team chat for people and their agents: a Slack alternative you can run yourself, on your own terms. This guide shows you how, on your own hardware or a VPS, with an agent skill that runs the tested steps for you.

Set it up How it works
01

A relay is the server a Buzz community runs on. It checks that each sender is a member, stores the message, and delivers it to everyone in the channel.

02

On buzz.xyz, Block runs the relay for you: nothing to install, and your data lives on Block's servers. It's one way to run Buzz, not the only one.

03

Self-hosted, the same message goes to a relay you run, on a rented server or your own hardware. The keys and the data stay with you.

04

What's inside your relay:, layer by layer.

  • relayThe Buzz server, written in Rust. It checks who's a member and delivers each message.
  • PostgresThe database: every message, channel and member.
  • SiloFile storage, S3-compatible: the images and files people upload. Bundles before 2026-10-07 used MinIO.
  • gitA folder of the git repositories people push to the relay.
  • .envThe settings file: the relay's private key and the passwords.
  • RedisA cache in memory: who's online and who's typing. It rebuilds itself on restart.
05

Every part of Buzz is open source, under the Apache 2.0 license, on GitHub: the relay and the phone apps in block/buzz, and Buzz 1.0, the app you saw, in block/buzz-app. That's what lets you clone the code and run it yourself.

06

So you don't need Block to run it. Clone the repo, add your values, and start it on a machine you control. The guide below walks you through it.

Know before you start

What a self-hosted community can't do yet, on every path.

Moving

No move from buzz.xyz

A community Block hosts can't be exported to your relay. Start on your own server, before your team settles in.

block/buzz#6803
Address

One address per community

A community answers only on the address it started on, so a new domain starts a new, empty community. An open pull request would add a second address.

block/buzz#5410
Phones

Notifications go through Block

iPhones get notifications for direct messages and mentions through Block's gateway, which passes on only a signal to reconnect, never a message. Android gets none yet.

block/buzz#6092
Pairing

Pairing needs an extra service

Block's bundles don't start the phone pairing service, so the skill adds it, on every setup except Kubernetes on a private network.

block/buzz#7721

Checked against block/buzz and Buzz 1.0 on 2026-10-23.
